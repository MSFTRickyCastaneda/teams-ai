# User Authentication

One of the most dramatic simplifications in Teams AI Library v2 is user authentication. BotBuilder requires complex dialog management with `OAuthPrompt`, `WaterfallDialog`, and state management. Teams AI v2 reduces this to simple `SignIn()` and `SignOut()` method calls.

## Overview

**BotBuilder approach:**
- Create `OAuthPrompt` dialog
- Manage dialog state with `ConversationState` and `UserState`
- Handle waterfall steps
- Implement interrupt logic for sign-out
- Manually manage token lifecycle

**Teams AI v2 approach:**
- Configure OAuth connection name
- Call `SignIn()` method
- Subscribe to `OnSignIn` event
- Use `IsSignedIn` property
- Call `SignOut()` method

# State Management

BotBuilder uses a complex state management system with `ConversationState`, `UserState`, state property accessors, and manual save operations. Teams AI Library v2 simplifies this with an intuitive `IStorage<string, object>` interface that automatically handles persistence.

## Overview

The key differences:

| BotBuilder | Teams AI v2 |
|------------|-------------|
| `ConversationState` / `UserState` | `IStorage<string, object>` |
| `CreateProperty<T>()` | `Get<T>()` / `Set()` |
| Manual `SaveChangesAsync()` | Automatic persistence |
| State accessors | Direct key-value access |
| Complex setup | Built-in and ready to use |

## User vs Conversation State

BotBuilder separates `UserState` and `ConversationState`. Teams AI v2 uses a single storage interface with scoping built into the key:

<Tabs groupId="migration-comparison">
  <TabItem value="BotBuilder" label="BotBuilder">
    ```csharp showLineNumbers
    public class MyBot : ActivityHandler
    {
        private readonly IStatePropertyAccessor<UserData> _userAccessor;
        private readonly IStatePropertyAccessor<ConversationData> _conversationAccessor;
        private readonly UserState _userState;
        private readonly ConversationState _conversationState;

        public MyBot(UserState userState, ConversationState conversationState)
        {
            _userState = userState;
            _conversationState = conversationState;
            _userAccessor = userState.CreateProperty<UserData>("UserData");
            _conversationAccessor = conversationState.CreateProperty<ConversationData>("ConversationData");
        }

        protected override async Task OnMessageActivityAsync(
            ITurnContext<IMessageActivity> turnContext,
            CancellationToken cancellationToken)
        {
            var userData = await _userAccessor.GetAsync(
                turnContext, 
                () => new UserData(), 
                cancellationToken);
            
            var conversationData = await _conversationAccessor.GetAsync(
                turnContext, 
                () => new ConversationData(), 
                cancellationToken);

            userData.MessageCount++;
            conversationData.Topic = "Migration";

            await _userState.SaveChangesAsync(turnContext, false, cancellationToken);
            await _conversationState.SaveChangesAsync(turnContext, false, cancellationToken);
        }
    }
    ```
  </TabItem>
  <TabItem value="Teams AI" label="Teams AI v2" default>
    ```csharp showLineNumbers
    [Message]
    public async Task OnMessage(
        [Context] MessageActivity activity,
        [Context] IContext.Client client,
        [Context] IStorage<string, object> storage)
    {
        // User-scoped data (key includes user ID)
        var userKey = $"user_{activity.From.Id}";
        var userData = storage.Get<UserData>(userKey, new UserData());
        userData.MessageCount++;
        storage.Set(userKey, userData);

        // Conversation-scoped data (key includes conversation ID)
        var convKey = $"conv_{activity.Conversation.Id}";
        var conversationData = storage.Get<ConversationData>(convKey, new ConversationData());
        conversationData.Topic = "Migration";
        storage.Set(convKey, conversationData);

        // Both automatically persisted
    }
    ```

## Complete Working Example

Here's a full example showing various state management patterns:

```csharp showLineNumbers title="MainController.cs"
using Microsoft.Teams.Api.Activities;
using Microsoft.Teams.Apps.Annotations;
using Microsoft.Teams.Apps;

[TeamsController("main")]
public class MainController
{
    [Message("/profile")]
    public async Task OnProfileCommand(
        [Context] MessageActivity activity,
        [Context] IContext.Client client,
        [Context] IStorage<string, object> storage)
    {
        var userId = activity.From.Id;
        var profileKey = $"user_profile_{userId}";
        
        var profile = storage.Get<UserProfile>(profileKey);
        
        if (profile == null)
        {
            await client.Send("No profile found. Use /setprofile <name> to create one.");
            return;
        }
        
        await client.Send($"Name: {profile.Name}, Age: {profile.Age}");
    }

    [Message(@"/setprofile (?<name>\w+) (?<age>\d+)")]
    public async Task OnSetProfileCommand(
        [Context] MessageActivity activity,
        [Context] IContext.Client client,
        [Context] IStorage<string, object> storage)
    {
        // Extract name and age from message using regex groups
        var match = System.Text.RegularExpressions.Regex.Match(
            activity.Text, 
            @"/setprofile (?<name>\w+) (?<age>\d+)");
        
        var name = match.Groups["name"].Value;
        var age = int.Parse(match.Groups["age"].Value);
        
        var userId = activity.From.Id;
        var profileKey = $"user_profile_{userId}";
        
        var profile = new UserProfile
        {
            Name = name,
            Age = age,
            CreatedAt = DateTime.UtcNow
        };
        
        storage.Set(profileKey, profile);
        
        await client.Send($"Profile created for {name}, age {age}");
    }

    [Message]
    public async Task OnMessage(
        [Context] MessageActivity activity,
        [Context] IContext.Client client,
        [Context] IStorage<string, object> storage)
    {
        // Track message count per conversation
        var convId = activity.Conversation.Id;
        var countKey = $"conv_messagecount_{convId}";
        
        var count = storage.Get<int>(countKey);
        count++;
        storage.Set(countKey, count);
        
        // Track user's last message time
        var userId = activity.From.Id;
        var lastMessageKey = $"user_lastmessage_{userId}";
        storage.Set(lastMessageKey, DateTime.UtcNow);
        
        await client.Send($"Message #{count} in this conversation");
    }
}

public class UserProfile
{
    public string Name { get; set; }
    public int Age { get; set; }
    public DateTime CreatedAt { get; set; }
}
```

## State Lifetime and Scoping

Teams AI v2 automatically scopes state based on the context:

```csharp
[Message]
public async Task OnMessage(
    [Context] MessageActivity activity,
    [Context] IStorage<string, object> storage)
{
    // Application-wide state (shared across all conversations)
    var appStats = storage.Get<AppStatistics>("app_stats", new AppStatistics());
    appStats.TotalMessages++;
    storage.Set("app_stats", appStats);
    
    // Conversation-scoped state
    var convKey = $"conv_{activity.Conversation.Id}";
    var convData = storage.Get<ConversationData>(convKey, new ConversationData());
    convData.MessageCount++;
    storage.Set(convKey, convData);
    
    // User-scoped state
    var userKey = $"user_{activity.From.Id}";
    var userData = storage.Get<UserData>(userKey, new UserData());
    userData.LastActivity = DateTime.UtcNow;
    storage.Set(userKey, userData);
    
    // User-conversation-scoped state
    var userConvKey = $"user_{activity.From.Id}_conv_{activity.Conversation.Id}";
    var userConvData = storage.Get<UserConversationData>(userConvKey, new UserConversationData());
    userConvData.Preferences.Add("dark-mode");
    storage.Set(userConvKey, userConvData);
}
```

## Key Benefits

1. **Simpler API**: Just `Get()`, `Set()`, `Delete()`, and `Has()`
2. **No Manual Saves**: Automatic persistence
3. **Type Safety**: Generic methods with type parameters
4. **Flexible Scoping**: Use key conventions for different scopes
5. **Easy Testing**: Simple interface to mock
6. **Less Boilerplate**: No state property accessors or state managers
